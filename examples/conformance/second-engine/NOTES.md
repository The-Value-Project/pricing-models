# NOTES — spec gaps and choices
(entry format: spec section | unclear | chosen | cases)

1. 4.1 / 6 | Unresolved references make every later check unsafe, yet 6 says report every failure found. | On any unresolved id the engine reports `unresolved_reference` (all it finds in the reference pass) and stops; other phases do not run. | model-id-mismatch
2. 4.7 | The spec lists no ISO 3166 country set. | A country code is any two uppercase letters; `EU` and `EEA` are the groupings. Anything else is `unknown_region` (e.g. `XX1`). Two-letter codes that are not real countries pass. | unknown-region-code
3. 7.1 step 4 | "Dependency is met only if the required object is selected" does not say when the dependency applies, or whether it is per product. | It applies only when the dependent object is present (module charged, tier chosen in any selection, product selected, package selected); the required object may be present in any selection of the deal. | dependency-unmet, dependency-met-by-addon
4. 7.1 step 6 | Direction and null handling of `prerequisite`; whether `relationship_not_modeled` needs the objects to be present. | `prerequisite`: subject present and related_to missing is `dependency_unmet`. `mutual_exclusion`: both present is `mutual_exclusion`. `relationship_not_modeled` (severity warning) is emitted whenever such a relationship exists in the model, whether or not its objects are selected. | relationship-mutual-exclusion, relationship-not-modeled-warns
5. 7.1 step 5 | Rules are text; the engine cannot evaluate them. | No rule is evaluated: one `unevaluated_rule` info warning lists all rule ids. `hard_block_rule` and `rule_warning` are never emitted, so a hard_block rule never blocks. | business-rules-unevaluated
6. 7.6 consumption rules | Warning granularity. | One `consumption_conditions_ignored` info warning per credit type that has a rule with non-null `conditions` (message names the credit type). | consumption-conditions-ignored
7. 7.4 table / Annex A `invalid_override` | "Targets nothing" and "invalid target" are not defined. | An override is invalid if its kind/type pair is not in the 7.4 table, its value is null (except `waived`), a module or credit_package target is not a charged line of the deal, a `credit_type_overage` target is not a credit type, or `custom_unit_price` on overage targets a type without `overage_price`. `total_deal` ignores `target_id`. A credit_type_overage override on a credit type that has no overage this deal is accepted. | negotiated-invalid-combination
8. 7.4 order | "For each charged module, in order: 1, 2, 3" vs three passes over all modules. | Per line, in line order: replacement (which then skips plan and bundle), else plan then bundle(s). Adjustments therefore list line by line. | bundles-overlap-compound, negotiated-fixed-price
9. 7.4 replacement | Whether a replaced line may still get plan/bundle; whether `waived` counts. | A line with any replacement override gets no plan or bundle adjustment (all three types). `fixed_price` = value x number of billing periods of the line's price (one for one_time). `custom_unit_price` recomputes the charge with a per_unit price at the line's quantities. Several replacements on one line apply in array order. | negotiated-fixed-price, negotiated-waived
10. 7.4 plans | Whether the plan's own eligibility (and a plan taken from `billing.plan_id`) is a "selected object" for `ineligible_selection`. | Yes, both. Ineligible plan: error or warning per policy, and its grants do not join pools. A plan or bundle adjustment below -100 is `invalid_percent`. | billing-plan-id-default, plan-targets-other-tier
11. 7.4 bundles | Several bundles, and the variant `enabled` override. | Bundles apply in `bundle_selections` order, compounding; a variant override replaces the bundle's own eligibility. A bundle needs every product id selected; otherwise `ineligible_selection` handling. Bundles adjust module lines only, not credit packages or overage. | bundle-partial-dropped, bundle-partial-is-error, bundles-overlap-compound
12. 7.4 plans on tiers | A module added by `module_selections` when plan `tier_ids` is non-empty. | It does not match (charged through no tier). `required` modules count as through-tier. | plan-targets-other-tier, plan-empty-targets-unrestricted, required-module-and-addon-targeting
13. 7.5 category | Category of a one-time credit package; whether overage is recurring. | A package with a `one_time` price is `one_time_fee`. Overage lines are `usage_overage` and count as recurring. | package-flat-price-ignores-count, one-time-charge
14. 7.6 DN-13 | Demand is a yearly billed quantity; pools have monthly/annual periods. | Demand is compared with each pool's quantity as is ("read in the pool's own period"), with no conversion between periods. `per_billing_period`, `concurrent` and `lifetime` pools compare the same way. The overage charge is the price's per-period rate x that year's largest overage. | overage-mixed-period-pools
15. 8 / DN-17 | `granted` when the largest overage is 0. | The first pool of the credit type (in build order). With overage, the pool giving the largest overage. -1 for unlimited. | overage-within-grant, overage-unlimited-grant
16. 8 | `overage_cost` when nothing is charged. | 0 for any determinate credit type without a charge (including throttle and hard_cap); null only when indeterminate. | overage-throttle-not-priced, overage-unknown-grant-indeterminate
17. 7.6 policy | Which tiers count for `conflicting_overage_policy`. | Only tiers of selections whose grants include the credit type, ignoring tier policy `unknown`. | conflicting-tier-overage-policies
18. 7.6 packages | Package units to the pool when the package selection count is >1. | pool += package quantity x selected count. A package with `rollover_policy: unknown` marks the credit type indeterminate. | overage-package-units-count
19. 7.7 mandatory manual | `invalid_discount` says such a discount is invalid but not whether it still applies. | It is reported `invalid_discount` and not applied (so no `missing_manual_value` follows). | mandatory-manual-discount-invalid
20. 7.7 base | "One-time fees are excluded" for `contract_total`; packages with one_time price. | Lines whose price period is one_time are excluded, unless a module line whose id is in `targets.module_ids`. `module` and `product` scopes include one-time module lines. | contract-discount-excludes-one-time, discount-scope-module
21. 9.3 applies_to | A discount over several lines has no single `line:<id>`. | Single line: `line:<id>` for module scope; a single product gives `product:<id>`; single credit type `credit_type:<id>`; otherwise (several lines/products/credit types) `contract_total`. | discount-scope-module, flat-discount-spread-in-proportion
22. 7.7 flat spread | Spreading when the base total is 0. | The whole amount goes to the first line; zero-amount adjustments are never recorded. | flat-discount-once-per-contract
23. 7.7 negotiated | Whether "An override is not discounted again" excludes lines with a phase 3 replacement or a negotiated discount from later discounts. | Not excluded: model discounts, negotiated discounts and `total_deal` overrides all act on running amounts, replaced lines included. | negotiated-capped, negotiated-discount-percentage, negotiated-price-meets-minimum
24. 7.7 stacking | "Earlier discount applied" with exclusive groups. | A group counts as applied when its chosen member applies. `max_discount` is decided by trial computation at the group's first position in the order; ties go to the first member. | exclusive-group-max-discount, exclusive-group-first-in-order, not-stackable-after-earlier-discount
25. 7.7 strategies | `step_tiers` gap between brackets; lookup key format. | A value in a gap gets 0. Key compare uses the canonical decimal string of the metric. An unresolved lookup follows `missing_strategy_inputs_handling`. | strategy-step-tiers, strategy-lookup-hit, strategy-lookup-missing-key-error, strategy-lookup-missing-key-zero
26. 7.8 product minimum | `applies_to` for several target products; which lines count for a product. | Lines with a non-null product_id (modules and packages) in the target products; overage lines have no product. `applies_to` names the first target product (or `contract_total` when targets are empty). Earlier true-ups count toward wider scopes only. | minimum-product-then-contract, minimum-annual-scope
27. 7.8 | Ineligible minimum; minimum with other currency. | Ineligible: silently skipped. Currency differing from the statement's: `mixed_currency`. | minimum-currency-must-match, minimum-not-needed
28. 9.1 / 9.4 annualized_total | A discount spread over recurring and one-time lines: its recurring part. | The recurring share is rounded once on its own and added to the rounded recurring lines, then divided by term/12 and rounded. If the whole adjustment is recurring, its rounded amount is used. | rounding-half-away-from-zero, rounding-none
29. 9.2 / 9.4 statement fields | `invoice_id`, `period.label` and output fields the spec does not define. | invoice_id = `inv-<config_id>`; period label "Contract total", end date = start + term months - 1 day; `computation_method` text is informational; `computation_notes` empty. | all statements
30. 5.3 | Unpriced items. | `unpriced_item` warning, line total 0, unit_price 0. | unpriced-item
31. 3.7 | Which currency a price has when a book applies. | Price currency (null -> model currency) must equal the statement currency (book currency when a book applies, else model). A mismatch is `mixed_currency`; overage prices are checked the same way. | mixed-currency-prices, price-book-null-multiplier-currency-mismatch, price-book-other-currency-multiplier
32. 7.3 | Several books match. | Exact country book wins; else grouping books; more than one grouping is `ambiguous_price_book`. A variant override beats the price book entry and the fallback multiplier. | price-book-grouping-match, variant-beats-price-book, price-book-entry-without-variant
33. 2.4 | `period_type`. | Only `contract_total` is produced; the runner takes no parameter, so `unsupported_period_type` is never emitted. | all
34. 7.1 step 7 / 7.7 | `discount_not_ordered` scope. | Checked for every discount that applies (mandatory eligible, or selected and eligible), not for dropped ones. | discount-not-in-order-list, discount-ineligible-selection-dropped
35. 4.4 / 7.1 | `module_selection_in_tier` vs `required` modules. | Only tier-included modules trigger the failure; selecting a required module that is not in the tier is accepted and the module is charged once. | module-selection-in-tier, required-module-and-addon-targeting
36. 9.2 line fields | `product_id` of a credit-package line is not defined. | The engine uses the package's owning product. The reference expected values use null. | package-per-unit-price, package-flat-price-ignores-count, overage-package-units-count
37. 9.2 `source_fields` | "Then the quantity entry (`config#` pointer)" does not say what the quantity entry is for an overage line or a package line. | The engine lists the price pointer only. The reference expected values add the credit type's `quantities` entry for an overage line and the `credit_package_selections` entry for a package line. | package-flat-price-ignores-count, overage-package-units-count, overage-pay-as-you-go, overage-mixed-period-pools
